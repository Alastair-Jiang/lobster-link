## 二、实测（15:16，6×5s，PerfCounter 每核）

| 核 | 忙占比 |
|---|---|
| cpu0–cpu11 | 44% – 88%（12 核均值 **~61%**） |
| **cpu12** | **0.9%** |
| **cpu13** | **0.3%** |
| **14 核总体均值** | **53.3%** |

**读法（与 `011` 一致，且更精确）**：
1. **并非"算力打满"**：14 核整体只有 **53%**，12 个活跃核约 61% → 仍有 ~40% 余量。
2. **有两颗核（cpu12/cpu13，LP-E 低功耗核）几乎完全没被调度**（0.9% / 0.3%）。Windows 把 LP-E 留给后台；
   PyTorch 的 OpenMP 线程落不上去。**这两颗核目前是纯浪费**。
3. **瓶颈是开销不是算力**：30 s 窗口内新建 ~22 个 python 进程（DataLoader 在 Windows 上按 `spawn` 反复起 worker），
   我们的模型只有 2.8 万参数 —— 时间花在进程创建与调度，不是 FLOPs。
